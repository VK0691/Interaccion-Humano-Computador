\section{Informe de la Tarea}

\subsection{Objetivos}

\subsubsection{General}

Analizar la interacción humano--computador del proceso de reserva
de tutorías académicas, identificando las personas involucradas,
el sistema, sus entradas y salidas, las disciplinas relacionadas
y los estilos de interacción necesarios para el desarrollo de
Tutoría Fácil UTA.

\subsubsection{Específicos}

\begin{itemize}

    \item Identificar a los usuarios directos e indirectos
    involucrados en el proceso de tutorías.

    \item Determinar las entradas, salidas y responsabilidades
    principales del sistema Tutoría Fácil UTA.

    \item Relacionar informática, psicología cognitiva,
    ergonomía y diseño con decisiones concretas de interacción.

\end{itemize}

\subsection{Desarrollo de la Tarea (Actividades a Desarrollar)}

\subsubsection{Problema identificado}

Actualmente la coordinación de tutorías se realiza mediante
mensajes de WhatsApp, hojas de cálculo y agendas personales.

El estudiante debe contactar al docente, esperar una respuesta,
proponer diferentes horarios y solicitar una confirmación.

Cuando necesita modificar una tutoría, normalmente debe iniciar
una nueva conversación.

Este proceso puede ocasionar:

\begin{itemize}
    \item demoras;
    \item confirmaciones ambiguas;
    \item selección de horarios ocupados;
    \item información desactualizada;
    \item necesidad de intercambiar múltiples mensajes.
\end{itemize}

Como respuesta a este problema se propone
\textbf{Tutoría Fácil UTA}, una aplicación web móvil que permita
consultar disponibilidad, reservar, confirmar y reprogramar
tutorías desde una única interfaz.

% ---------------------------------------------------------
\subsubsection{Personas que intervienen}

\textbf{Estudiante}

El estudiante constituye el usuario principal del sistema.

Su objetivo es consultar la disponibilidad de un docente,
seleccionar una fecha y horario, reservar una tutoría,
recibir una confirmación clara y posteriormente reprogramarla
cuando sea necesario.

La evidencia E1 describe a Laura, estudiante de 20 años,
consultando horarios desde su teléfono mientras viaja en bus.

\vspace{0.2cm}

\textbf{Docente}

El docente constituye un usuario secundario.

Su participación se relaciona principalmente con la disponibilidad
de horarios y las solicitudes de tutoría.

La evidencia E6 establece que los docentes actualmente reciben
solicitudes fuera de horario y actualizan manualmente su
disponibilidad.

\vspace{0.2cm}

\textbf{Secretaría}

La secretaría participa indirectamente en el proceso.

La evidencia E7 indica que transcribe cambios a una hoja de
cálculo y puede conservar información desactualizada.

% ---------------------------------------------------------
\subsubsection{Sistema}

Tutoría Fácil UTA deberá procesar, almacenar y comunicar
información relacionada con:

\begin{itemize}
    \item docentes;
    \item fechas;
    \item disponibilidad;
    \item horarios;
    \item reservas;
    \item estados;
    \item confirmaciones;
    \item reprogramaciones.
\end{itemize}

El sistema debe impedir que un estudiante seleccione un horario
que ya se encuentre ocupado y proporcionar una respuesta clara
después de cada acción relevante.

\subsubsection{Disciplinas relacionadas con IHC}

\textbf{Informática}

Permite gestionar de forma estructurada la disponibilidad,
las reservas y los estados de las tutorías, reduciendo
inconsistencias derivadas del manejo manual.

Se relaciona con E3 y E7.

\vspace{0.2cm}

\textbf{Psicología cognitiva}

Permite analizar cómo el usuario percibe, recuerda y procesa
la información.

En Tutoría Fácil UTA se busca disminuir la cantidad de información
que el estudiante debe memorizar mediante resúmenes y estados visibles.

Se relaciona con E4 y E5.

\vspace{0.2cm}

\textbf{Ergonomía}

Permite adaptar el sistema a las condiciones reales de uso.

Las evidencias indican que la aplicación puede utilizarse desde
un teléfono mientras el usuario se encuentra en movimiento y
que ciertos usuarios utilizan teclado, ampliación al 200\% y
lector de pantalla.

Se relaciona con E1 y E2.

\vspace{0.2cm}

\textbf{Diseño}

El diseño permite organizar los controles, estados, etiquetas
y acciones mediante una jerarquía consistente y comprensible.

Se relaciona con E2 y E9.

% ---------------------------------------------------------
\subsubsection{Estilos de interacción}

\textbf{Menús}

Se emplearán menús y opciones para acceder a acciones como:

\begin{itemize}
    \item reservar tutoría;
    \item ver horarios;
    \item consultar mis tutorías;
    \item reprogramar.
\end{itemize}

\textbf{Formularios}

Se utilizarán controles para seleccionar información como:

\begin{itemize}
    \item docente;
    \item fecha;
    \item modalidad;
    \item horario.
\end{itemize}

\textbf{Manipulación directa}

El usuario podrá seleccionar directamente un horario visible.

Por ejemplo:

\begin{center}
\textbf{10:00 -- Disponible}
\end{center}

Después de seleccionarlo:

\begin{center}
\textbf{10:00 -- Seleccionado}
\end{center}

\subsection{Conclusiones}

\begin{itemize}

    \item El estudiante debe encontrarse en el centro del flujo
    de interacción, debido a que actualmente depende de varias
    conversaciones manuales para completar una tutoría.

    \item Tutoría Fácil UTA debe mantener visibles los estados
    de disponibilidad, selección y confirmación para reducir
    ambigüedad y prevenir errores.

    \item La accesibilidad, ergonomía y consistencia deben
    incorporarse desde las primeras etapas del diseño y no
    únicamente como correcciones posteriores.

\end{itemize}
