\section{Informe de la Tarea}

\subsection{Objetivos}

\subsubsection{General}

Construir y evaluar un prototipo móvil interactivo de
Tutoría Fácil UTA que permita completar la reserva de una
tutoría y comenzar una reprogramación sin necesidad de
explicación verbal previa.

\subsubsection{Específicos}

\begin{itemize}

    \item Diseñar cuatro pantallas conectadas aplicando las
    decisiones obtenidas en las actividades anteriores.

    \item Configurar un flujo principal y una ruta de
    reprogramación funcional.

    \item Realizar una prueba cruzada, registrar un hallazgo
    observable y aplicar una mejora concreta.

\end{itemize}

% =========================================================
\subsection{Instrucciones}

El prototipo debe construirse utilizando Figma Design o
Penpot con fidelidad baja o media.

Debe permitir realizar el siguiente recorrido:

\begin{center}
Inicio $\rightarrow$ Horarios $\rightarrow$ Resumen
$\rightarrow$ Confirmación
\end{center}

También debe existir una ruta de reprogramación.

Posteriormente, el prototipo debe entregarse a una persona
de otro equipo sin explicarle cómo utilizarlo.

La tarea será:

\begin{center}
\textbf{``Reserve una tutoría para el jueves y luego cambie el horario.''}
\end{center}

\subsection{Desarrollo de la Tarea (Actividades a Desarrollar)}

\subsubsection{Pantalla 1: Inicio y búsqueda}

La primera pantalla debe comunicar claramente el objetivo
de la aplicación.

Debe incluir:

\begin{itemize}
    \item nombre Tutoría Fácil UTA;
    \item mensaje principal;
    \item búsqueda de docente o asignatura;
    \item acceso a Ver horarios;
    \item acceso a Mis tutorías.
\end{itemize}

Un ejemplo de distribución sería:

\bocetocaja{%
\centering

\textbf{Tutoría Fácil UTA}\\[0.2cm]

Encuentra y reserva una tutoría académica.\\[0.3cm]

\fbox{\parbox{0.60\textwidth}{\centering Buscar docente o asignatura}}\\[0.3cm]

Ing. Juan Pérez\\
Programación\\[0.2cm]

\fbox{Ver horarios}\\[0.2cm]

\fbox{Mis tutorías}
}

% ---------------------------------------------------------
\subsubsection{Pantalla 2: Docente y horario}

La segunda pantalla permitirá consultar disponibilidad y
seleccionar una fecha y un horario.

Debe mostrar:

\begin{itemize}
    \item docente;
    \item asignatura;
    \item calendario;
    \item fecha seleccionada;
    \item horarios disponibles;
    \item horarios ocupados;
    \item horario seleccionado;
    \item acción Continuar.
\end{itemize}

Los estados deberán contener texto.

Por ejemplo:

\begin{itemize}
    \item 09:00 -- Disponible.
    \item 10:00 -- Disponible.
    \item 11:00 -- Ocupado.
    \item 12:00 -- Seleccionado.
\end{itemize}

Los horarios ocupados no podrán seleccionarse.

También se considerarán estados para conexiones variables.

\textbf{Estado de carga:}

\begin{center}
\textit{Consultando horarios...}
\end{center}

\textbf{Estado de error:}

\begin{center}
\textit{No pudimos cargar los horarios. Intentar nuevamente.}
\end{center}

% ---------------------------------------------------------
\subsubsection{Pantalla 3: Resumen y confirmación}

La tercera pantalla permitirá revisar los datos antes de
la confirmación definitiva.

Debe incluir:

\begin{itemize}
    \item docente;
    \item fecha;
    \item hora;
    \item modalidad;
    \item Confirmar tutoría;
    \item Cambiar horario.
\end{itemize}

Ejemplo:

\bocetocaja{%
\centering
\textbf{Revisa tu tutoría}\\[0.3cm]

\raggedright
\textbf{Docente:} Ing. Juan Pérez\\
\textbf{Fecha:} Jueves 8 de octubre\\
\textbf{Hora:} 12:00\\
\textbf{Modalidad:} Presencial\\[0.3cm]

\centering
\fbox{Confirmar tutoría}\\[0.2cm]

\fbox{Cambiar horario}
}

La opción Cambiar horario permite corregir la selección antes
de confirmar definitivamente.

% ---------------------------------------------------------
\subsubsection{Pantalla 4: Confirmación y reprogramación}

La última pantalla mostrará un estado inequívoco.

Debe incluir:

\begin{itemize}
    \item Tutoría confirmada;
    \item docente;
    \item asignatura;
    \item fecha;
    \item hora;
    \item modalidad;
    \item estado CONFIRMADA;
    \item acción Reprogramar;
    \item acción Volver al inicio.
\end{itemize}

Ejemplo:

\bocetocaja{%
\centering
\textbf{\ding{51} Tutoría confirmada}\\[0.3cm]

\raggedright
\textbf{Docente:} Ing. Juan Pérez\\
\textbf{Asignatura:} Programación\\
\textbf{Fecha:} Jueves 8 de octubre\\
\textbf{Hora:} 12:00\\
\textbf{Modalidad:} Presencial\\
\textbf{Estado:} CONFIRMADA\\[0.3cm]

\centering
\fbox{Reprogramar}\\[0.2cm]

\fbox{Volver al inicio}
}

\subsection{Resultados obtenidos}

Como resultado se obtiene un prototipo navegable compuesto
por cuatro pantallas conectadas.

El flujo permite:

\begin{itemize}
    \item buscar una tutoría;
    \item seleccionar fecha y horario;
    \item diferenciar opciones disponibles y ocupadas;
    \item revisar los datos antes de confirmar;
    \item recibir una confirmación inequívoca;
    \item iniciar una reprogramación.
\end{itemize}

Los resultados de la evaluación deberán completarse únicamente
después de ejecutar la prueba real.

\subsection{Conclusiones}

\begin{itemize}

    \item El prototipo debe demostrar la aplicación de las
    decisiones de IHC y no limitarse únicamente a una
    presentación visual.

    \item La prueba cruzada permite detectar problemas reales
    de comprensión que pueden pasar desapercibidos durante
    el diseño inicial.

    \item La iteración solo es válida cuando la modificación
    realizada responde directamente a un hallazgo observado.

\end{itemize}

% =========================================================
\subsection{Recomendaciones}

\begin{itemize}

    \item No inventar tiempos, comentarios ni hallazgos de
    la prueba.

    \item Verificar que el enlace de Figma funcione en una
    ventana privada antes de entregar.

    \item Mantener las capturas antes y después de la mejora.

    \item Verificar que el flujo de reprogramación funcione
    desde la pantalla de confirmación.

    \item Relacionar el commit de la mejora con el issue o PR
    correspondiente.

\end{itemize}
